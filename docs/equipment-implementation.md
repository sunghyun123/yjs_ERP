# 영전사 전산 현황 구현 기록

기준: `전산운영대장 페이지/영전사_전산_현황_기획서.md` v2.0 (2026-09-22).

## 구현된 기능

- 일반 메뉴 `/assets`: 기본 2층, 1·2·3층 선택, 검색과 미배치 결과, 사용 상태별/층별 집계, 간략 배치도와 선택 상세, 확대·축소·화면 맞춤.
- 사무실 왼쪽 8석·중앙 3석·오른쪽 6석 및 오른쪽 대표이사실·회의실·탕비실의 상대 위치를 유지했다. 계단·화장실은 표시하지 않는다. 기본 캔버스는 1000 × 650 논리 좌표이다.
- 관리자: 배치 이동·키보드 이동·크기/캔버스 크기 수정·추가·삭제, 구역/인원/장비 배정, 로컬 변경 저장·취소, 장비/수량품/인원/서비스 등록·수정.
- `/assets/stock`: 장소별 수량품 조회, 관리자 원자적 증감 및 실사 수량 입력. 미확인과 0개를 구분하고 실사 확인일과 일반 수정일을 분리한다.
- 휴대폰은 담당자 상세를 열면 별도 RPC로 자동 조회하여 이메일과 함께 표시한다. 추가 확인 버튼은 없으며, 기존 화이트리스트 권한 검증을 유지한다. 최초 응답에는 포함하지 않는다. 스펙 등급과 교체 우선순위는 관리자 전용 테이블에만 보존하며, 관리자가 관리정보 버튼을 눌렀을 때 조회·수정할 수 있다.
- 서비스 과금은 금액·통화·주기·과금 단위·인원을 분리하고 원본을 보존한다. 상태는 미측정이며 갱신일은 한국 날짜 기준으로 표시한다.

사무실 왼쪽 8석은 장비 미등록이며 실제 장비 없음으로 해석하지 않는다. 공용 서랍은 임시 위치이다. 모델 미확인 값과 원본 메모를 보존한다. Google의 `16.80$/인`과 원본 연 환산액 `168.0$/인`, 도메인 ③의 연 주기와 2년 결제 메모는 확인 필요로 남겼다. 이전 폐기 자료와 백업 ZIP은 이관 입력으로 사용하지 않았다.

초기 SQL은 원본에서 생성하며 Git에서 제외한 `tmp/equipment/seed.sql`에 저장한다. 원본 업무 정보가 들어 있으므로 공개 산출물에 포함하지 않는다. 실행은 다음과 같다. 두 명령 모두 운영 DB에 연결하지 않는다.

```powershell
node scripts/prepare-equipment-seed.cjs
node scripts/verify-equipment-seed.cjs
```

원본의 행 수가 바뀌면 생성기가 중단되므로 매핑을 다시 검토해야 한다. 이관은 `source_key`와 결정적 UUID를 사용하고 재실행 시 기존 편집을 덮어쓰지 않는다. 최초 이관은 일반 사용자의 자산 등록 전에 실행한다.

## DB와 저장 규칙

마이그레이션: `supabase/migrations/20260922090000_equipment.sql`.

- 기존 `is_whitelisted()` / `is_admin()` 및 실제 `auth.identities` 기반 권한 판정을 재사용한다.
- 모든 장비 테이블에서 RLS를 적용한다. 일반 정보는 화이트리스트 사용자, 관리자 정보는 관리자만 읽는다. 연락처 테이블의 휴대폰 컬럼은 직접 SELECT 권한이 없다.
- 클라이언트 직접 DML은 허용하지 않고 관리자 검증 RPC로 변경한다. `security definer` 함수는 고정 search_path와 명시적 실행 권한을 갖는다.
- 층 버전과 항목 버전으로 오래된 저장을 거부한다. 배치·배정 저장은 단일 트랜잭션이며 저장 중 장비 변경은 advisory lock으로 직렬화한다.
- 같은 층의 구역 연결, 순환 금지, 캔버스 경계, 활성 참조는 DB에서 검사한다. 구역과 내부 자리의 시각적 겹침은 허용한다.
- 배치 삭제는 soft delete이며 연결 자산/수량품은 미배치로 보존한다. 상위 구역 삭제 시 하위 블록의 구역 연결만 해제한다. 퇴사는 자리 배정을 해제하고 장비는 유지한다. 자산 삭제 시 서비스의 물리 자산 연결을 해제한다.
- 수량 미확인은 null, 확인 수량은 0 이상 정수라는 DB 제약을 둔다. 증감에는 기존 버전이 필요하며 실사일은 실사 수량 입력 시에만 갱신한다.
- 자산번호는 분류별 DB 카운터에서 중복 없이 생성한다. 감사 로그는 기존 `audit_log`를 사용하고 UUID는 JSON 안에 보존한다. 수정자와 수정시각은 트리거가 기록한다.

## 검증 결과 및 남은 검토

- 전체 Vitest 216개 통과 (장비 기능 27개 포함).
- `npx tsc --noEmit`, 변경 파일 ESLint, 프로덕션 빌드 통과.
- PGlite PostgreSQL에서 실제 마이그레이션·기존 권한 헬퍼 실행, 읽기/쓰기 권한, 휴대폰/관리자 정보 분리, 실패 시 롤백, 버전 충돌, 음수 금지, 삭제 시 장비 보존, 자산번호 생성 등을 검증했다.
- 실제 원본에서 생성한 seed를 로컬 PostgreSQL에 두 번 적용하여 인원 19명·업무 PC 14건·서비스 12건·2층 직원 배정 18건이 유지됨을 검증했다.
- 로컬 개발 미리보기의 HTTP 200과 서버 렌더링을 확인했다. 미리보기 전용 경로는 제거했고 프로덕션 결과에는 포함되지 않는다.
- 전체 ESLint는 작업 전부터 있던 `scripts/register-path-alias.cjs`의 require 관련 오류 2건과 기존 React 라이브러리 경고 4건이 남는다. 이번 변경 파일에는 린트 오류가 없다.
- 연결된 브라우저가 없어 실제 화면 캡처·일반 노트북/모바일 가독성·드래그/포커스/브라우저 뒤로가기의 상호작용 검증은 미완료다. 배치 변경 이탈 안내는 링크 이동·폼 제출·beforeunload 및 Navigation API로 구현했다. 뒤로/앞으로 이동은 취소 가능한 navigate 이벤트에서 사용자 선택을 확인한다. 브라우저가 취소를 허용하지 않는 이동은 강제로 가두지 않는다. [HTML 표준의 navigate 이벤트 규칙](https://html.spec.whatwg.org/multipage/nav-history-apis.html#the-navigate-event)을 따른다. Navigation API 미지원 브라우저와 실제 브라우저 상호작용은 추가 확인이 필요하다.
- 운영 DB 마이그레이션·seed 실행, 실제 로그인 계정의 권한/저장 검증, 앱 배포는 수행하지 않았다.

## 운영 적용 순서

### 대형 모니터 분류 및 서비스 정렬 추가

- 기존 장비 마이그레이션이 적용된 DB에는 `supabase/migrations/20260922100000_equipment_large_monitors.sql`을 추가 적용한다. 초기 seed를 재실행할 필요는 없다.
- 수량품 분류에 `대형 모니터`를 추가하고 기존 수량품의 분류 수정도 허용한다. 분류 변경은 수량·실사 확인일을 보존하며, 기존 관리자 권한·버전 검증·감사 기록을 유지한다. 기존 데이터의 분류를 자동 추정하여 변경하지 않는다.
- 서비스는 갱신일 오름차순으로 표시하며, 지난 날짜도 확인을 위해 앞에 둔다. 날짜가 없는 서비스는 마지막에 표시한다. 갱신이 필요 없는 서비스는 갱신일을 비워 둔다.

### 최초 적용

1. 운영 DB 백업과 기존 화이트리스트/관리자 헬퍼가 적용되어 있는지 확인한다.
2. 위 마이그레이션을 적용한다. 과거 rollback 파일을 포함해 기존 마이그레이션 전체를 재실행하지 않는다.
3. 검토한 `tmp/equipment/seed.sql`을 적용한다. 최초 seed 전에는 초기 데이터 미준비 오류가 표시된다.
4. 실제 직원/관리자 계정으로 `/assets`와 `/assets/stock`의 읽기·권한 차단·저장·동시 수정 등을 검증하고, 노트북/모바일 화면을 확인한다.
5. 코드 배포 후 실사 미확정 항목을 현장과 대조한다. 실사 완료 시 수량과 최종확인일을 입력하고, 개별 장비를 모두 등록한 장소의 수량 미확인 분류를 해제한다.
