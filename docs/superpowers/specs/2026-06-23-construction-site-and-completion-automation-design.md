# 공사현장 드롭다운 + 준공 자동화 설계

작성일: 2026-06-23
상태: 설계 확정 (구현 대기)

실배포 후 첫 운영 피드백 2건을 반영한다. 두 기능은 서로 독립적이므로 **별도 커밋(가능하면 별도 PR)**으로 구현한다.

---

## 배경 — 현재 달성률이 안 바뀌는 이유

준공을 찍어도 수주대장 달성률이 안 바뀐다는 피드백의 원인:

- 수주대장 테이블(`OrdersTable`)이 보여주는 `달성율`은 **`수주` 테이블에 저장된 정적 컬럼**이다. 구ERP import 이후 아무 코드도 갱신하지 않는다.
- OrderForm 우측 / 공사이력(`/progress`)이 보여주는 "공정 달성률"은 **실시간 계산값**(`Σ공사이력.성과금액 ÷ 하도적용금액 × 100`)이며 저장되지 않는다.
- 매출손익(`/sales`)은 `공사이력.성과금액`을 월별·공사별로 합산한다. 즉 **`공사이력`이 성과의 단일 정본**이다 (기존 원칙: 공사현황.xlsx → 공사이력 단독 적재, 매출손익.xlsx 적재 금지).

따라서 준공 자동화는 **`공사이력`에 준공정산 행을 적재 + `수주.달성율`을 직접 세팅**하는 방향으로 정본 구조를 깨지 않고 구현한다.

## 기능 A — 공사현장 드롭다운 + 관리자 CRUD

### 목표
수주 등록/수정 시 `공사현장`을 자유 입력이 아닌 드롭다운으로 선택한다. 현재는 광명·안양뿐이지만 향후 현장이 늘어날 것을 대비해 **관리자 페이지에서 추가/삭제** 가능하게 한다.

### 데이터 구조 (결정: A-1)
새 테이블 `공사현장`을 만들되, **`수주.공사현장`은 기존처럼 문자열 컬럼으로 유지**한다. 드롭다운은 `공사현장` 테이블에서 옵션 목록만 읽고, 선택한 `현장명` 문자열을 `수주.공사현장`에 저장한다.

```
공사현장
  id        bigint PK
  현장명     text UNIQUE NOT NULL
  생성일     timestamptz default now()
```

근거: 현장 수가 적고(현재 2개), `수주.공사현장`을 FK로 정규화하면 기존 자유입력 데이터 전수 마이그레이션 + 삭제 제약(FK) 처리가 필요해 이득보다 비용이 크다. 문자열 유지 시 현장을 삭제해도 기존 수주 데이터가 깨지지 않는다.

### 마이그레이션
1. `공사현장` 테이블 생성.
2. 시드: `광명`, `안양` + 기존 `수주.공사현장`의 distinct non-null 값.
3. RLS: 읽기는 화이트리스트 사용자, **쓰기(insert/update/delete)는 admin 전용** (기존 거래처·공사단가 정책과 동일하게 `is_admin()` 기반).

### UI 변경
- **관리자 페이지** `/admin/sites`: 기존 `/admin/gongmu` 패턴을 따른다(목록 테이블 + 추가 인풋 + 행별 삭제). 관리자 네비게이션에 "공사현장" 링크 추가.
- **OrderForm**: `공사현장` 필드를 `Input`(자유입력) → `Select`(드롭다운)으로 교체. 옵션은 서버 컴포넌트(`orders/page.tsx`)에서 `공사현장` 테이블을 조회해 `공사현장목록: string[]` props로 주입한다. 기존 값이 목록에 없을 수도 있으므로(과거 자유입력), edit 모드에서 현재 값이 옵션에 없으면 그 값도 임시 옵션으로 표시한다.

### 삭제 정책
하드 삭제. `공사현장` 행 삭제는 옵션 목록에서만 제거되며, 이미 그 현장명을 쓰는 `수주` 행에는 영향 없음(문자열 보존).

## 기능 B — 준공 자동화

### 확정 규칙
- 준공 성과 기준: **준공액 공급가(부가세 제외, ex-VAT)** — 기존 매출손익 ex-VAT 체계와 일관.
- 준공정산 매출손익 반영 월: **준공일** 기준.
- 준공 완료된 공사: 공사이력(`/progress`) 입력 드롭다운에서 **숨김**.
- 준공정산 행 식별: **`공사이력`에 전용 boolean 컬럼 추가 (결정: B-1)**.
- **준공은 오직 수주대장(`OrderForm`)에서 수동으로만 찍힌다.** 공사이력 달성률이 100%를 넘어도 자동으로 준공 처리되는 일은 절대 없다.
- **준공/해제는 사용자가 직접 입력한 공사이력 행을 절대 삭제·변경하지 않는다.** 시스템이 만지는 것은 자동 생성한 `준공정산=true` 행 하나뿐이다.

### 두 가지 "달성률"의 구분 (중요)
이 둘은 의미가 다르므로 절대 합치지 않는다.

1. **공정 달성률(공사이력 추정치)** — `Σ공사이력.성과금액 ÷ 하도적용금액 × 100`. OrderForm 우측·`/progress`에서 실시간 계산해 보여주는 값. 공사이력은 "진행한 공사 규모를 수치로 환산한 추정"이라 **정확한 금액이 아니다.** 따라서 **100%를 초과해도 그대로 표시한다(clamp 금지).** 이 값이 100%를 넘는다고 해서 준공이 자동으로 찍히지 않는다.
2. **달성율(준공 완료 플래그)** — `수주.달성율` 저장 컬럼. **수주대장에서 준공을 수동으로 찍었을 때만** 100으로 세팅된다. 수주대장 테이블이 보여주는 값이며, "이 공사는 끝났다"는 확정 사실을 의미한다.

### 데이터 구조
`공사이력`에 컬럼 추가:
```
공사이력.준공정산  boolean NOT NULL default false
```
한 수주당 준공정산 행은 최대 1개. 정합성 로직이 문자열 마커가 아닌 이 플래그로 행을 식별한다.

### 동작 — 준공 완료 저장 시 (`OrderForm`의 준공 저장 핸들러 확장)
준공여부가 `true`로 저장될 때:
1. **검증**: `준공액_공급가`가 없으면 저장 차단(토스트 경고).
2. `수주` 업데이트: `준공여부=true`, `준공일`, `준공액_공급가`, **`달성율=100`**.
   - 준공=완료 플래그로 취급해 달성률은 성과/하도 비율과 무관하게 100으로 고정한다.
3. 기존 성과 누계 계산: `Σ공사이력.성과금액` (단, `준공정산=true` 행은 제외).
4. `delta = 준공액_공급가 − Σ` 계산.
5. **준공정산 행 upsert**: `수주_id`, `작업일자=준공일`, `성과금액=delta`, `작업내용='준공정산(자동)'`, `준공정산=true`, `담당공무_id=수주.공무담당자_id`.
   - 이미 준공정산 행이 있으면(재저장) 그 행을 갱신(idempotent). 없으면 insert.
6. 결과: 매출손익의 해당 공사 총성과 = 준공액 공급가, 수주대장 `달성율` = 100.
   - 단, OrderForm·`/progress`의 **공정 달성률(추정치)은 별도 계산값이며 100% 고정이 아니다.** 준공정산 행이 추가되면 그 값에 자연스럽게 반영될 뿐 clamp하지 않는다.

### 동작 — 준공 해제 시 (체크 해제 후 저장) — 데이터 손실 없음 보장
실수 준공은 반드시 발생하므로, 해제는 **안전하게 원복**되어야 한다. 핵심: **사용자가 직접 입력한 공사이력은 한 줄도 지워지지 않는다.**

1. 해제 저장 전 **확인 다이얼로그**를 띄운다: "준공을 해제하면 자동 생성된 준공정산 성과 1건이 제거되고 달성률이 재계산됩니다. 직접 입력하신 공사이력은 그대로 보존됩니다."
2. `수주` 업데이트: `준공여부=false`, `준공일=null`, `준공액_공급가=null`.
3. **자동 생성한 준공정산 행(`준공정산=true`)만** 삭제. 그 외 공사이력(`준공정산=false`)은 절대 건드리지 않는다.
4. `달성율` 재계산: 남은 성과 누계 ÷ 하도적용금액 × 100 (하도적용금액이 없으면 `null`).
   - 삭제 대상이 자동 행 하나로 한정되므로, 사용자 데이터 손실 경로가 코드상 존재하지 않는다(삭제 쿼리는 항상 `eq('준공정산', true)`를 포함).

### 엣지 케이스
- `delta` 음수(기존 누계 > 준공액): 하향 정산 허용. 저장 전 확인 경고를 띄운다(예: "기존 성과 누계가 준공액보다 큽니다. 성과가 하향 조정됩니다.").
- 하도적용금액이 없거나 0: 달성률은 100으로 세팅(플래그), 해제 시 재계산은 null.
- 준공일 미입력: 기존 동작 유지하되 준공정산 행 작업일자가 필요하므로 준공일도 필수 검증에 포함.

### 표시
- **OrdersTable**: `준공여부=true`이면 `수주.달성율`(=100)을 표시. 준공 완료 뱃지와 함께 "100%"가 자연스럽게 보인다.
- **OrderForm**: 공정 달성률(추정치)과 기성 달성률은 기존대로 계산값으로 표시(100% 초과 가능). 준공 공사는 "준공완료" 상태를 명확히 보여주되, 추정 달성률을 100%로 덮어쓰지 않는다.
- `/progress` 입력 폼의 공사 선택 드롭다운은 `준공여부=true`인 공사를 옵션에서 제외. (현황 조회 탭은 그대로 노출.)

### 정합성 보증
- 성과의 단일 정본(`공사이력`)을 유지한다. 매출손익은 여전히 `공사이력.성과금액` 합산만 사용하므로 이중 적재가 발생하지 않는다.
- 준공정산 행이 `Σ성과` 계산에서 자기 자신을 다시 포함하지 않도록 항상 `준공정산=false`만 합산해 delta를 구한다.

## 구현 분할 (커밋 단위)
1. **마이그레이션**: `공사현장` 테이블 + RLS + 시드, `공사이력.준공정산` 컬럼. (DB)
2. **기능 A**: `/admin/sites` 페이지 + OrderForm 드롭다운 + orders/page 옵션 주입.
3. **기능 B**: 준공 저장/해제 로직(해제 확인 다이얼로그 포함), 수주대장 달성률 표시, progress 드롭다운 필터.
4. `src/types/database.ts` 타입 갱신(두 기능에 걸침 — 1번과 함께).

테스트: 준공 정산 delta 계산(양수/음수/재저장/해제 원복)은 순수 함수로 분리해 단위 테스트한다.
