# ERP MCP 커넥터 (Claude Desktop 로컬 확장) 설계

- 작성일: 2026-10-27
- 상태: 설계 확정, 구현 계획 작성 전
- 범위: 최소 시험판. 써보고 쓸모가 확인되면 도구와 칸을 늘린다.

## 목적

Claude Desktop 채팅창에서 ERP 데이터를 자연어로 묻는다.

- "올해 완결된 공사 몇 건인지 불러와줘"
- "이번달 매출손익이 플러스인 공사와 마이너스인 공사를 나눠서 알려줘"

## 확정된 결정

| # | 결정 | 근거 |
|---|---|---|
| 1 | 공사별 **계산 완료 행**을 주고, 거르기·나누기는 Claude가 한다 | 손익 공식이 한 곳에만 남는다. 원본을 주면 Claude가 대화마다 공식을 새로 지어 화면 숫자와 갈라진다 |
| 2 | 완결 = `수주.준공여부 = true`, 연도는 `준공일`로 판단 | 수주대장 '준공완료' 필터·도넛 '완료'와 같은 판정. 시공상태·정산상태는 시험판에서 제외 |
| 3 | 도구 2개 (공사 목록 / 공사별 손익) | 손익 집계에는 그 해 움직임이 있는 공사만 나와서, 손익 도구 하나로 완결 건수를 세면 조용히 적게 나온다 |
| 4 | 로컬 확장 `yj-erp.mcpb`를 새로 만들어 yjs_erp 레포 `mcp/`에 둔다 | API(보내는 쪽)와 relay(받는 쪽)가 한 레포에서 같이 바뀐다 |
| 5 | 새 키 `ERP_MCP_API_KEY` | 사장님 PC에서 키가 새도 열리는 건 MCP 라우트 2개뿐이다. 대시보드 키와 독립적으로 교체할 수 있다 |

## 구조

```
사장님 PC                                     ERP 서버 (erp.yjsboard.com)
┌──────────────────────────┐   HTTPS +        ┌─────────────────────────────────────┐
│ Claude Desktop           │   Bearer         │ /api/mcp/constructions   (도구 ①)    │
│   └ yj-erp.mcpb (relay)  │ ───────────────▶ │ /api/mcp/profit          (도구 ②)    │
│      키 = 확장 설정에 저장  │ ERP_MCP_API_KEY  │   └ Bearer 검사 (유일한 문지기)        │
└──────────────────────────┘                  │   └ service_role → DB (RLS 우회)     │
                                              │   └ _lib/공사별손익.ts  ◀── sales/page │
                                              └─────────────────────────────────────┘
```

### 경계

- **공식은 `src/app/(dashboard)/_lib/공사별손익.ts` 한 곳.** 매출손익 화면(anon 키 + 세션)과 MCP 라우트(service_role)가 같은 함수를 부르고, supabase 클라이언트만 인자로 다르게 넘긴다. `load성과재료(supabase)`와 같은 모양이다.
  - `load…(supabase, year)`: 조회 (투입실적·공사단가·`load성과재료`)
  - `aggregate공사별손익(재료, year)`: 순수 계산. 현재 `sales/page.tsx` 38~132줄의 로직을 그대로 옮긴다. 반환값은 `pivotData`(공사별 연간·월별 성과/투입/손익, 준공 반영)와 `monthly`(월별 합계)
- **relay는 계산하지 않는다.** JSON을 받아 텍스트로 넘긴다. 크기 상한을 넘으면 자르지 않고 에러를 낸다.
- **읽기 전용.** GET 라우트 2개만 만들고 쓰기 도구는 없다.
- **날짜 판단은 서버가 한다.** `"current"`는 서버가 `partsKST()`로 해석하고, 해석한 값을 응답의 `기준`에 적어 돌려준다.
- **세기와 더하기도 서버가 한다.** 건수와 합계는 서버가 계산해서 같이 준다.

### 파일

- 신규: `src/app/(dashboard)/_lib/공사별손익.ts`, `src/app/api/mcp/constructions/route.ts`, `src/app/api/mcp/profit/route.ts`, `mcp/` (yjs_backoffice `mcp/`의 manifest·relay·테스트 골격 복사)
- 수정: `src/app/(dashboard)/sales/page.tsx` (계산부를 함수 호출로 교체, 렌더는 그대로)

## 도구 ① `get_constructions`: 공사 목록

입력:

- `completed_year` (선택): 숫자 또는 `"current"`. 주면 `준공여부 = true`이고 `준공일`이 그 해인 공사만 준다. 안 주면 전체를 준다.

출력:

```json
{
  "기준": { "준공연도": 2026 },
  "건수": 87,
  "공사": [
    { "지중no": "AA26-012", "공사명": "...", "준공여부": true, "준공일": "2026-03-14" }
  ]
}
```

- 금액은 내보내지 않는다(노출 최소화).
- 필터가 없으면 `기준`은 `{}`이다.
- 연도 필터가 있으면 `"제외": { "준공됐지만 준공일 없음": N }`을 붙인다. 이런 공사는 어느 해에도 셀 수 없으므로 0처럼 숨기지 않고 건수를 남긴다(구ERP 이관분 등). 필터가 없으면 이 칸은 없다.

## 도구 ② `get_profit`: 공사별 손익

입력:

- `year` (선택): 숫자 또는 `"current"`. 기본값은 `"current"`.
- `month` (선택): 1~12 또는 `"current"`. 주면 그 달 값만 주고, 안 주면 연간 합을 준다.

출력:

```json
{
  "기준": { "연도": 2026, "월": 10 },
  "단위": "원",
  "합계": { "성과": 412000000, "투입": 389000000, "손익": 23000000 },
  "공사": [
    { "지중no": "AA26-031", "공사명": "...", "성과": 18200000, "투입": 12100000, "손익": 6100000, "준공반영액": 4000000 }
  ],
  "제외": { "성과·투입 모두 0인 공사": 41 }
}
```

- 월을 안 주면 `기준.월`은 `null`이다.
- 행은 손익 큰 순으로 정렬한다.
- `준공반영액`은 그 기간 성과 중 준공 잔여분으로 얹힌 금액이다. 없으면 칸을 생략한다.
- 그 기간에 성과와 투입이 모두 0인 공사는 행에서 빼고, 뺀 건수를 `제외`에 남긴다.
- `합계`는 제외된 공사까지 포함한 전체 합이다. 매출손익 화면의 같은 기간 합계와 같아야 한다.
- 금액은 원 단위 정수로 반올림한다. 손익은 반올림한 성과에서 반올림한 투입을 빼서 낸다(행마다, 합계도). 읽는 쪽이 다시 빼 봐도 맞아야 한다.

## 입력 값이 비어 있을 때

파라미터가 **아예 없을 때만** 기본값을 쓴다. `month=`처럼 값이 빈 문자열이면 400을 돌려준다.

## 입력 검증

- 연도가 2000~2100 밖이거나, 월이 1~12도 `"current"`도 아니면 **400**을 준다.
- 매출손익 화면처럼 잘못된 연도를 올해로 바꾸지 않는다. "2025년"을 물었는데 2026년 숫자를 받아 2025년이라고 답하는 사고를 막기 위해서다.

## 에러 처리

원칙: 의심스러우면 빈 결과로 넘기지 말고 에러를 낸다.

| 위치 | 상황 | 처리 |
|---|---|---|
| ERP 라우트 | `ERP_MCP_API_KEY` 미설정 | 500 |
| | 키 불일치 | 401 |
| | 입력 오류 | 400 |
| | DB 조회 실패 | 500 + 메시지. `200 + 빈 배열`로 내보내지 않는다 |
| | 도구 ①에서 필터 없이 수주 전체가 0건 | 500 (조회가 깨진 것으로 본다) |
| | 도구 ①에서 특정 연도 준공 0건 | 정상, `건수: 0` |
| relay | ERP 응답이 2xx가 아님 | MCP 도구 에러(`isError: true`)로 상태코드와 메시지를 전달 |
| | 네트워크 실패, 30초 타임아웃 | 위와 같음 |
| | 응답이 크기 상한(15만 자)을 넘음 | 자르지 않고 에러 |

1000행 상한은 `fetchAllRows`의 페이지 넘김이 처리한다.

## 테스트

1. **리팩터 동등성 (가장 중요):** 옮기기 전에 현재 page 로직으로 2025·2026년 `pivotData`와 `monthly`를 JSON으로 떠 두고, 옮긴 뒤 새 함수 결과와 한 글자까지 비교한다. 운영 DB를 읽기만 하는 일회성 스크립트이며 커밋하지 않는다.
2. **단위 테스트 (vitest):** 입력 해석(`"current"`, 범위 밖 연도, `month=13`, `month=abc`), 월 자르기, `제외` 건수, 합계에 제외분 포함, 손익순 정렬, 준공연도 필터, 수주 전체 0건이면 에러.
3. **relay 테스트 (`node --test`):** 401·500이 `isError`로 바뀌는지, 크기 상한, URL·쿼리 조립.

## 수동 검증 (배포 후)

- "올해 완결된 공사 몇 건?" → 수주대장 '준공완료' 필터 + 2026 건수와 일치해야 한다.
- "이번달 손익 플러스/마이너스 나눠줘" → 매출손익 화면 해당 월의 성과·투입·손익 합계와 일치해야 한다.

## 배포 순서

1. ERP `.env.production`에 `ERP_MCP_API_KEY`를 넣고 배포한다. 새 라우트가 생기므로 재빌드가 필요하다.
2. `curl`로 401(키 없음)과 200(키 있음)을 확인한다.
3. `.mcpb`를 설치하고 확장 설정에 키를 넣는다.

## 범위 밖 (추후)

## 보안 메모

- 새 라우트는 service_role로 RLS를 우회한다. 문지기는 Bearer 검사 한 줄뿐이다.
- 도구 결과는 Anthropic의 Claude로 전송된다. 공사별 금액이 회사 밖 서비스로 나가는 것이므로 사장님 승인이 필요하다.
