# 네비게이션 내성 워크스페이스 (Navigation-Resilient Workspace)

> 작성일: 2026-06-25
> 상태: 설계 확정 (구현은 슬라이스 순서로)
> 티어: A (앱 전역 클라이언트 상태 + 네비게이션을 가로지르는 컨텍스트 = 새 패턴)

## 1. 문제

대시보드 페이지를 이동하면 그 페이지의 React 상태(선택한 공사, 입력 중인 값, 검색어, 날짜 필터)가
**통째로 메모리에서 사라진다.** 실사용에서 이게 반복적인 분노를 만든다:

> 공사이력을 등록하려고 투입실적 입력 탭에서 공사를 검색·선택했는데, 마지막 투입일이 이상해서
> 현황 탭에 잠깐 확인하러 갔다 돌아오니 검색해둔 공사가 사라져 있다. 다시 검색한다. 당황해서 또 까먹는다. 반복.

이전 ERP는 로컬 실행파일 기반이라 엑셀 시트처럼 탭을 오가도 각 탭의 입력이 보존됐다. 그 감각을 웹에서 되살린다.

이것은 "웹의 한계"가 아니다. Next.js App Router에서 형제 라우트 이동은 페이지 컴포넌트를 언마운트하지만,
**상위 레이아웃은 언마운트되지 않는다.** 레이아웃 스코프에 클라이언트 상태를 두면 네비게이션을 가로질러 생존한다.

## 2. 목표 / 비목표

**목표**
- 대시보드 페이지를 오가도 각 페이지가 **자기 입력/검색/필터 상태를 보존**한다.
- 페이지 간 상태는 **서로 독립**이다(커플링 없음). 투입실적에서 고른 공사가 공사이력을 건드리지 않는다.
- 같은 메커니즘을 입력 폼과 현황(목록) 페이지에 **동일하게** 적용한다.

**비목표 (YAGNI)**
- 전역 단일 "현재 작업 공사" (검토했으나 기각 — 대량 입력 시 스티키·커플링이 거슬림).
- "기억 중" 같은 상태 광고 UI (배지·점). 채워져 있으면 보존된 것, 비었으면 미입력 또는 버그.
- 분할 화면(두 페이지 동시 표시). 이 설계 위에 추후 얹을 수 있으나 지금 범위 아님.
- 전체 브라우저 종료 후 복원까지는 요구하지 않음. (sessionStorage로 탭 새로고침 생존은 옵션.)

## 3. 기각된 대안

- **전역 단일 컨텍스트(X안)**: 하나의 "현재 공사"가 모든 페이지를 따라다님. 한 공사 깊이 작업엔 최고지만,
  여러 공사를 빠르게 갈아끼우는 대량 입력에서 전역 칩이 계속 "틀린 공사"로 들러붙고 페이지가 커플링됨. 기각.
- **페이지별 localStorage 분산 저장**: provider 없이 각 폼이 스토리지에 직접 저장. 로직이 흩어져
  설명·유지가 어렵고, 페이지별 슬라이스를 한곳에서 보는 이점이 없음. 기각.
- **통합 워크스페이스(단일 라우트 인페이지 탭, 전부 마운트 유지)**: "엑셀 탭"에 가장 충실하고 상태가
  본질적으로 보존되지만, 세 페이지를 한 라우트로 재편 + 사이드바 의미 변경 = 배포 직후 블라스트 반경이 큼.
  이 설계(provider)는 그 방향의 토대가 되므로, 점진적으로 진화 가능. 지금은 기각.

## 4. 설계

### 4.1 메커니즘

`(dashboard)/layout.tsx`(서버 컴포넌트, 형제 라우트 이동 시 비언마운트)의 `{children}`을
**`WorkspaceProvider`(클라이언트)**로 감싼다. 이 provider는 **페이지별 UI 상태 캐시**다:

```ts
// 페이지 키 → 그 페이지의 보존 상태 (서로 독립)
type WorkspaceState = {
  inputForm?: InputFormDraft       // 투입실적 입력
  progressForm?: ProgressFormDraft // 공사이력 입력
  inputHistory?: HistoryFilter     // 투입실적 현황
  progressHistory?: HistoryFilter  // 공사이력 현황
}
```

- `useWorkspaceSlice<T>(key)` 훅: 해당 페이지의 상태 조각과 setter를 반환. 페이지는 자기 키만 읽고 쓴다.
- provider가 레이아웃에 상주 → 네비게이션을 가로질러 생존.
- **단일 책임**: provider는 "페이지별 UI 상태 보관" 하나만 한다. 비즈니스 로직 없음.

### 4.2 새로고침 생존 (옵션, 채택)

`WorkspaceState`를 `sessionStorage`에 미러링한다. 탭을 새로고침해도 보존되되, 브라우저/탭을 닫으면 사라진다
(오래된 초안이 영구히 남는 부작용 방지). **하이드레이션 미스매치 방지**를 위해 초기값은 빈 상태로 두고,
마운트 직후(`useEffect`)에 sessionStorage에서 읽어 채운다.

### 4.3 UI 원칙

- 상태 광고 UI 없음 (배지·점·전역 칩 전부 없음).
- 입력 폼: 공사 선택 후에도 검색창은 **편집 가능**. 클릭 → Ctrl+A → 새 지중No 붙여넣기로 즉시 교체.
  (현재 `InputForm`이 이미 이 동작 — readonly로 잠그지 않는다.)
- 현황 페이지: 검색어·날짜 필터·정렬·페이지 인덱스가 보존된다.

## 5. 슬라이스 (구현 순서 = PR 단위)

### Slice 1 — Provider 인프라 + 입력 폼 2개
- `(dashboard)/_components/WorkspaceProvider.tsx` 신규 (Context + `useWorkspaceSlice` + sessionStorage 미러).
- `(dashboard)/layout.tsx`에서 `{children}` 래핑.
- `InputForm`(투입실적 입력): 검색어·선택수주·투입일·투입구분 수량·외주 값을 `inputForm` 슬라이스로 이전.
- `ProgressInputForm`(공사이력 입력): 선택수주·작업일자·성과금액 등을 `progressForm` 슬라이스로 이전.
- 기존 URL 딥링크(`?수주_id=`, `?날짜=`)는 유지: 마운트 시 URL 우선 → 없으면 보존 상태 → 둘 다 없으면 빈 상태.

### Slice 2 — 공사이력 현황
- `ProgressHistoryTable`은 이미 클라 fetch + 로컬 state. `dateFrom`/`dateTo`/`searchQuery`를
  `progressHistory` 슬라이스로 이전하기만 하면 됨. 저위험·소규모.

### Slice 3 — 투입실적 현황 (가장 무거움, 마지막)
- 현재 `input/page.tsx`가 **서버에서** 날짜 범위로 투입실적을 조회해 `HistoryTable`에 props로 내림.
  날짜 필터가 URL(`router.push`) 기반이라 키 입력마다 풀 페이지 네비게이션 → 끊김.
- `HistoryTable`을 **클라이언트 self-fetch**로 전환(공사이력 현황과 동일 패턴): 날짜·검색어·정렬·페이지를
  `inputHistory` 슬라이스 로컬 state로. 날짜 변경 시 클라에서 fetch(디바운스).
- **부수 효과(이득)**: URL 네비게이션 제거로 [앞서 식별된 투입실적 현황 날짜 입력 끊김]이 함께 해결됨.
- 잃는 것: 날짜 범위가 URL에서 빠져 공유 링크/새로고침 시 기간이 이번 달로 리셋(공사이력 현황과 동일, 허용).

## 6. 데이터 흐름 (입력 폼 초기화 규칙)

마운트 시 폼 선택/값의 출처 우선순위:
1. URL 파라미터(`?수주_id`, `?날짜`) — 명시적 딥링크가 최우선 (+ 보존 슬라이스에도 동기화)
2. 보존된 슬라이스 상태 — 있으면 복원
3. 둘 다 없으면 빈 상태(기본 날짜 = 오늘 KST)

## 7. 엣지 케이스

- **하이드레이션**: 초기 렌더는 빈 상태 → 마운트 후 sessionStorage 주입. SSR/CSR 마크업 불일치 없음.
- **독립성**: 한 페이지 슬라이스 변경이 다른 슬라이스를 건드리지 않음(객체 키 분리).
- **딥링크 충돌**: URL `수주_id`가 보존 상태와 다르면 URL 우선(사용자가 명시적으로 그 공사로 진입한 것).
- **저장 후**: 입력 저장 성공 후 슬라이스를 비울지 유지할지는 구현 시 결정 — 기본은 "유지"(같은 공사 연속 입력 흔함).

## 8. 테스트

- 순수 로직(초기화 우선순위, 슬라이스 read/write, sessionStorage 직렬화)은 단위 테스트(vitest).
- 컴포넌트 상호작용(네비 후 복원)은 현재 RTL 미설치 → 수동 검증 체크리스트로 대체:
  입력→현황→입력 복원 / 페이지 간 독립 / 빠른 교체(Ctrl+A 붙여넣기) / 새로고침 생존.

## 9. 향후 (이 설계 위에)

- 분할 화면(두 페이지 동시) — provider 상태를 그대로 재사용.
- 통합 인페이지 탭 워크스페이스 — 라우트 통합 시에도 슬라이스 모델 유지.
