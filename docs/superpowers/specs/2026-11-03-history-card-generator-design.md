# 공사이력카드 자동 생성 (시공통보서 PDF → 씽크와이즈 카드 텍스트) 기획서

- 작성일: 2026-11-03
- 상태: 기획 확정. 구현 계획(plan) 작성 전
- 요청: 사장님. 시공통보서를 주면 AI가 공사이력카드를 써 주게 한다
- 작업 티어: **A** (외부 AI 호출·시크릿·외부 입력(PDF)·회계 금액). 전역 5게이트 적용한마음1단지아파트
- 사전 조사: `thinkwise-ops` 레포 `ops-log.md` 2026-11-02 항목 (웹 씽크와이즈 직접 연동은 기각, 이유는 아래 "범위 밖")

## 1. 목적

담당자가 ERP에서 시공통보서 PDF를 올리면, 씽크와이즈에 바로 붙여 넣을 수 있는 **공사이력카드 텍스트**가 화면에 나온다.

- 지금: 담당자가 통보서를 보고 카드를 손으로 쓰고, 번호도 손으로 붙인다
- 이후: ERP에서 카드를 만들고 복사해서 월간공사계획 맵에 붙여 넣는다 (담당자 맵 백업은 지금처럼 그 텍스트를 다시 붙여 넣는다)
- 들여쓰기(탭) 텍스트를 씽크와이즈에 붙여 넣으면 가지 구조로 들어간다 (사용자 확인)

## 2. 확정된 결정

| # | 결정 | 근거 (사용자 답) |
|---|---|---|
| 1 | **카드 생성만.** 수주 자동 등록은 하지 않는다. 카드 생성 기능은 DB에 **쓰지 않는다** | 초기 기획에 없었고, 잘못 들어가면 위험이 크다. 확인 버튼을 둬도 쓰다 보면 생각 없이 누른다 |
| 2 | 번호는 **제안만** (A안): 선택한 머리글자의 ERP 마지막 번호 + 1, 화면에 "수주 등록 시 확정" 표시 | 지금 담당자들이 하는 방식과 같다 |
| 3 | 머리글자 규칙은 **관리자 페이지에서 미리 정해 두고**, 사용자는 생성 화면에서 하나를 고른다 | 규칙이 곧 바뀐다 (JY·JG 정우전설 계약 종료) |

| 5 | PDF는 **서버가 1쪽만 잘라** OpenAI에 보낸다 (`pdf-lib`). 미리보기 없음 | 무엇이 밖으로 나가는지 서버가 정한다. 미리보기는 필요 없다 |
| 6 | 접수 날짜 = **시공통보일자** | 사용자 결정 |
| 7 | 진행사항·향후계획은 **제목만**. 공사시행은 **AI 초안** (틀려도 담당자가 고친다) | 사장님 요구 |
| 8 | twdx 다운로드는 **v1에서 뺀다** | 텍스트 붙여 넣기로 충분. 필요해지면 `thinkwise-ops/twdx_maker.py`를 TS로 옮긴다 (zip 함정 4가지 있음) |
| 9 | AI는 **회사 결제 OpenAI API 키**를 쓴다. **이 기능 전용 새 키**를 만들어 서버 env `OPENAI_API_KEY`에만 둔다 | 다른 프로젝트 키를 같이 쓰면 한쪽에서 새거나 교체할 때 같이 끊긴다. `NEXT_PUBLIC_` 접두사 금지 (브라우저 JS에 문자열로 박힌다) |

## 4. 카드 형식 (코드가 만든다)

`공사이력카드 예시.png`(thinkwise-ops) 기준. 들여쓰기는 **탭 1개 = 1단계**.

```
{번호}. {공사명}
	접수
		{YY.MM.DD} 시공통보서 접수
		공급가액
			{공급가액 천원}천원
		영전사금액
			{영전사금액 천원}천원
	진행사항
	공사시행
		{공사시행 초안 줄들}
	향후계획
```

- 번호: 기존 수주가 있으면 그 `지중no`, 없으면 제안 번호
- 공사명: 기존 수주가 있으면 ERP `공사명`, 없으면 통보서 공사명 (예시 카드 제목이 ERP 표기와 같은지 구현 전에 실데이터 2~3건으로 확인)
- 날짜: 시공통보일자를 `YY.MM.DD`로 (예: `26.01.08`). **문자열만 다루고 `new Date()`를 쓰지 않는다** (타임존 창이 생길 자리를 아예 안 만든다)
- 천원 표기: 예시 카드는 영전사금액 9,943.8천원을 **9,943천원**(버림)으로 적었다. 기존 `gongmu/_lib/erp-실적.ts`의 `천원()`은 **반올림**이다. → 구현 게이트1에서 사용자에게 버림/반올림 확인 후 결정
- 공사시행 초안: 줄 앞에 날짜를 붙이지 않는다 (아직 시행 전). 초안임을 알 수 있게 첫 줄에 `(AI 초안)` 같은 표시를 넣을지 게이트1에서 결정

## 5. 데이터 흐름

```
브라우저                       yjs_erp 서버 (route handler, Node 런타임)              OpenAI
────────                       ────────────────────────────────────────             ──────
머리글자 id + PDF  ──POST──▶  ① 세션 확인 (로그인·화이트리스트)
 (multipart)                   ② 파일 검사: PDF 매직바이트, 크기 상한(예 20MB)
                               ③ pdf-lib로 1쪽만 새 PDF로 추출
                               ④ OpenAI 호출 (1쪽 PDF + 추출 지시)      ──────▶  JSON
                               ⑤ JSON 검증 (zod)                        ◀──────
                               ⑥ 검산: 공급가액 + 부가세 = 계약금액 ?
                               ⑦ ERP 조회 (읽기만):
                                   - 공사번호로 기존 수주 찾기
                                   - 머리글자 규칙 + 마지막 번호
                               ⑧ 금액 계산 + 카드 텍스트 조립
카드 텍스트 + 경고  ◀──────── ⑨ 응답 (저장 없음, PDF 디스크에 안 씀)
```

### 5.1 AI가 돌려줄 JSON (안)

```ts
{
  공사번호: string        // "3917-2025-3862 (01)" 원문 그대로
  공사명: string
  시공통보일자: string     // "2026-01-08"
  사업소명: string | null
  계약금액: number         // 원, VAT 포함
  공급가액: number         // 원
  부가가치세: number       // 원
  공사개요: string | null
  공사기간_시작: string | null
  공사기간_끝: string | null
  공사시행초안: string[]   // 2~5줄, 공사개요·공사기간 근거
}
```

- OpenAI의 구조화 출력(JSON schema 강제)을 쓴다. 모델·API 형태(Responses API의 PDF 파일 입력 등)는 구현 시 공식 문서로 확인한다 (기억으로 쓰지 않는다)
- 읽지 못한 칸은 지어내지 말고 `null`로 돌려주라고 지시한다. 금액 칸이 `null`이면 카드의 그 칸에 `확인 필요`를 넣고 경고를 띄운다
- 통보서 1쪽은 **스캔 이미지**다 (텍스트 층 없음). 비전 입력이 필요하다

### 5.2 검산 (AI 읽기 오류 잡기)

- `공급가액 + 부가가치세 === 계약금액`이 아니면 경고: "통보서 금액을 다시 확인하세요 (공급가 + 부가세 ≠ 계약금액)". 카드는 그대로 보여 준다
- 예시 통보서: 49,302,664 + 4,930,266 = 54,232,930 (일치)
- 이 검산은 "숫자 셋 중 하나가 틀렸다"만 잡는다. 셋이 같이 틀리면 못 잡는다 → 화면 문구에 "금액은 통보서와 대조하세요"를 상시 표시

### 5.3 기존 수주 찾기

- 공사번호를 **숫자만 남겨** 비교한다. ERP에는 대시 없이 저장된 행이 있다 (조사 때 평촌동70 건을 대시 포함 검색으로 놓쳤다)
- `(01)` 같은 차수 꼬리를 어떻게 저장하는지 실데이터로 확인하고 비교 규칙을 정한다 (포함/제외)
- 결과는 세 갈래:
  - 0건: 신규 → 제안 번호 + 통보서 금액으로 계산
  - 1건: 그 수주의 `지중no`·`공사명`·금액 사용. 화면에 "ERP 등록된 공사" 표시
  - 2건 이상: 첫 행을 고르지 말고 경고 + 후보 지중no 나열 (금액은 통보서 기준)
- 찾은 수주의 원청사가 선택한 머리글자 규칙과 다르면 경고 (머리글자를 잘못 골랐을 가능성)

### 5.4 금액

- **공급가액**: 기존 수주 있으면 `수주금액_공급가`, 없으면 통보서 공급가액
- **영전사금액** = 하도적용 = 공급가 × (1 − 보험료율) × 하도전용율
  - 기존 수주: 그 행의 `보험료율`·`하도전용율`로 계산. **`orders/_lib/completion.ts`의 함수를 재사용**한다 (공식을 새로 쓰지 않는다 — 같은 값을 계산하는 곳이 늘면 언젠가 갈라진다)
  - 신규: 머리글자 규칙에 연결된 `거래처`의 `보험료제외율`·`하도전용율`로 계산 (수주폼이 원청사 선택 시 채우는 값과 같은 출처)
  - 요율 단위(소수 0.075 vs 퍼센트 7.5)가 `수주`·`거래처`에서 같은지 구현 전 확인. `OrderForm.tsx` 295~313줄은 퍼센트를 100으로 나눠 쓴다
  - 요율이 없으면 `completion.ts`에 엄격판(`calc하도적용금액`, null 반환)과 표시판(`calc하도적용표시금액`, 공급가 그대로)이 있다. 카드에는 **엄격판**을 쓰고 null이면 `확인 필요` + 경고 (요율 없는 공급가를 영전사금액이라고 적으면 조용히 틀린 숫자가 된다)
- 준공 후 계산서 금액이 더 정확하다는 예외는 v1 범위 밖 (통보서 접수 시점엔 계산서가 없다)

### 5.5 번호 제안

- 기존 `수주.지중no` 중 `^{머리글자}{YY}-\d+$`에 맞는 것의 최대 번호 + 1, 3자리 0채움 (`JY26-136`)
- `YY`는 **시공통보일자의 연도**로 한다 (서버 시계를 안 읽는다). 연말에 받은 다음 해 통보서 등 예외가 있으면 게이트1에서 사용자와 정한다
- 동시에 두 사람이 만들면 같은 번호가 제안될 수 있다. 제안일 뿐이고 확정은 수주 등록 때라 허용한다 (화면 문구로 알린다)
- 숫자 비교는 문자열이 아니라 정수로 (`"99" > "100"` 함정)

## 6. 머리글자 규칙 (관리자 페이지)

새 테이블 1개 + `admin/` 아래 새 화면 1개. **이건 DB 쓰기**(관리자 전용)이고, 카드 생성 기능 자체의 "읽기만" 원칙과는 별개다.

테이블 안: `이력카드_머리글자`

| 칸 | 뜻 |
|---|---|
| id | |
| 머리글자 | `JY`, `SY`, `CG` … (2글자 대문자, unique) |
| 이름 | 화면 표시용 (`정우전설`) |
| 거래처_id | 요율을 가져올 원청사 (FK → 거래처). 없을 수 있음 (아래) |
| 사용 | 생성 화면에 보일지 (계약 끝난 규칙은 지우지 말고 끈다 — 지난 번호의 뜻이 남아야 한다) |
| 정렬 | |

- 초기 데이터: JY·JG = 정우전설, SY·SG = 에스제이이, CG = 삼천리, MY = 민수, TY = 총가공사
- **확인할 것** (구현 게이트1):
  - JY와 JG의 차이 (법인 구분인가? Y/G 뒷글자 뜻) — 같은 거래처를 가리켜도 번호열은 따로다
  - 민수·총가공사는 `거래처` 행이 있나. 없으면 요율을 어디서 가져오나 (규칙 테이블에 요율 칸을 직접 둘지)
- RLS: 다른 업무 테이블과 같은 `is_whitelisted()` 정책. 쓰기를 관리자로 좁힐지는 기존 `admin/` 화면들의 방식을 따른다 (`admin/rates`·`admin/clients` 참고)

## 7. 보안·운영

- **키**: `OPENAI_API_KEY`는 서버 전용. route handler에서만 읽는다. `.env.production`에 추가 후 서버 env라 `pm2 reload`로 반영 (재빌드 불필요 — `NEXT_PUBLIC_`이 아니므로)
- **문지기**: 이 route는 OpenAI 요금을 쓰므로, 로그인한 화이트리스트 사용자만 부르게 세션을 확인한다. service_role 라우트(대시보드·MCP용 Bearer)와 섞지 않는다
- **밖으로 나가는 것**: 통보서 1쪽 (공사번호·금액·현장대리인 이름 등)이 OpenAI로 간다. **사장님께 한 줄 보고**하고 시작한다. 2~9쪽(예산서·명세서)은 안 보낸다
- **저장 안 함**: PDF와 결과를 디스크·DB에 남기지 않는다. 서버 로그에 PDF 내용·AI 응답 원문을 찍지 않는다 (오류 시엔 단계명과 상태코드만)
- **비용·남용**: 요청당 파일 1개, 크기 상한. 필요하면 사용자당 분당 횟수 제한 (v1은 상한만)
- **상태코드**: PDF 아님·용량 초과·머리글자 미선택 = 400 / 세션 없음 = 401 / OpenAI 실패·시간 초과 = 502 (우리 서버는 멀쩡하고 상류가 실패) / OpenAI 응답이 스키마에 안 맞음 = 502
- **실패를 조용히 넘기지 않는다**: AI가 JSON 대신 빈 값을 주거나 칸이 다 `null`이면 "읽지 못했다"로 실패 처리. 빈 카드를 성공처럼 보여 주지 않는다

- 카드 조립 함수 (순수 함수, AI·DB 없이): 신규/기존 수주, 요율 없음, 금액 `null`, 들여쓰기·탭 문자, 날짜 형식
