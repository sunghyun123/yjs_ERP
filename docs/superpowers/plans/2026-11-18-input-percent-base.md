# PR-D — 입력 화면 진도 % 기준을 준공액으로 (준공 공사)

- 작성: 2026-11-18 (PR-D 기획 세션)
- 진행 문서: `docs/superpowers/specs/2026-11-17-revenue-simplification-roadmap.md` (세션 규칙 블록부터 읽기)
- 티어: A (회계 정합성 — 입력 금액이 곧 매출)
- 앞 결정: §7-C 8 ① "입력 화면 % 수주 기준 → PR-D로 따로 기획"

## 1. 문제

입력 화면에서 %를 원으로 바꾸는 기준 금액이 **수주금액**이다.

- `progress/_components/ProgressInputForm.tsx:206-211` (새 입력)
- `progress/_components/이력수정Sheet.tsx:61-66` (수정)

두 곳 모두 `수주금액_공급가 × (1−보험료율) × 하도전용율`이다. 반면 미입력 탭 목표(`_lib/미입력.ts:94`)와 자동배분(`_lib/자동배분.ts:88`)은 같은 식에 **준공액**을 넣는다. 그래서:

- 감액 공사: 100%를 넣으면 미입력 탭에서 '입력 초과'가 된다. 경고("저장 후 누계가 100%를 넘습니다")도 수주 기준이라 **안 뜬다**.
- 증액 공사: 100%를 넣어도 미입력 탭에 '남은'이 남는다.

PR-C(#63)로 준공 보정이 꺼진 뒤라 초과는 곧바로 매출 과다다.

### 실측 (2026-11-18, 운영 DB 읽기)

| 항목 | 값 |
| --- | --- |
| 준공 공사 / 준공액 있음 | 370 / 293 |
| 준공액 = 수주금액 | 255 |
| 감액 | 27건, 공급가 합 −150,001,975 |
| 증액 | 11건, 공급가 합 +41,179,325 |
| 감액 공사 중 지금 초과(1천원 넘게) | 6건 (최대 JY25-096 −850,103원) — 대부분 11-18 정정에서 처리됨 |
| 준공 안 된 공사 / 그중 준공액 있음 | 293 / 2 |

**이 PR이 막는 범위:** 준공 *뒤* 입력(①). 공사 중에는 준공액이 없으므로(293건 중 2건만 있음) 수주 기준이 유일한 숫자다. 공사 중 100% 입력 → 나중에 감액 준공 → 초과(②)는 그대로 남고 미입력 탭 '입력 초과' 칸으로 감시한다(§7-C 8 결정 유지).

## 2. 게이트 1 — 결정

**(A) 채택: 기준 금액 = 준공 목표가 있으면 준공액, 없으면 수주금액.**
근거(조성현): 미입력 탭 목표와 100%가 같아져야 하니까.

대가: 준공을 찍는 순간 같은 공사의 % 의미가 바뀐다(어제 95% → 오늘 110%로 보일 수 있음). 저장값(원)은 안 바뀐다. 화면에 기준 라벨을 붙여 드러낸다.

기각:
- (B) % 수주 기준 유지 + 준공 공사에 준공액 기준 경고·남은 금액 추가 — 100%를 넣으면 여전히 넘치고, 막는 수단이 경고 한 줄뿐. 한 화면에 '100%'와 '목표' 두 기준이 생긴다.
- (C) 준공 공사는 % 입력을 끄고 원 + "남은 금액 넣기" 버튼 — % 의미는 안 바뀌지만 범위가 크고, 나눠 넣던 방식을 원으로 직접 계산해야 한다.

범위 밖(표시만 하고 입력을 안 만들어 초과를 만들지 않음): 수주대장 달성률(`orders/_lib/completion.ts`), 공무 주간보고 달성률(`WeeklyReportForm.tsx:191`), 홈 `ActiveProjects`의 `수주.달성율` 컬럼.

## 3. 규칙 — "준공 목표가 있다"의 정의

미입력 탭과 **글자 그대로 같은 조건**을 쓴다(`미입력.ts:84·90`): `준공여부 && 준공일 && 준공액_공급가 != null`.

- 준공액은 있는데 준공여부가 false인 2건 → 수주 기준(미입력 탭도 준공 전으로 본다).
- 준공인데 준공일이 비었음 → 수주 기준(미입력 탭은 '제외'로 센다. 맞출 목표가 없다).
- 보험료율·하도전용율 중 하나라도 null → 지금처럼 null(% 입력 불가, 원 모드 강제). 미입력 탭은 요율이 없어도 목표를 계산하지만(`calc하도적용표시금액`, 관대), 입력 쪽은 % 자체가 꺼지므로 두 쪽이 다른 숫자를 내는 경우는 없다.

## 4. 구현

### Task 1 — 기준 함수 하나 (`progress/_lib/percent.ts`)

```ts
export type 입력기준 = { 금액: number; 기준: '준공액' | '수주금액' }
export function calc입력기준금액(s: {
  준공여부: boolean; 준공일: string | null; 준공액_공급가: number | null
  수주금액_공급가: number | null; 보험료율: number | null; 하도전용율: number | null
}): 입력기준 | null
```

- 요율 null → null. 준공 목표 있음 → 준공액, 아니면 수주금액(null이면 null).
- 금액 = `calc하도적용표시금액(기준값, 보험료율, 하도전용율)` — 미입력 목표와 **같은 함수**로 곱해 반올림 차이가 생길 자리를 없앤다.
- 테스트(`percent.test.ts`) 먼저:
  1. 준공 전 → 수주금액 기준
  2. 준공 + 준공일 + 준공액 → 준공액 기준
  3. 준공인데 준공일 null → 수주금액 기준
  4. 준공 전인데 준공액 있음 → 수주금액 기준
  5. 요율 null → null
  6. **계약 테스트:** 같은 행으로 `build미입력`(또는 그 목표 계산)과 `calc입력기준금액(...).금액`이 같다 — 두 파일이 앞으로 갈라지면 여기서 깨진다.

### Task 3 — 두 화면이 함수를 쓰게

- `ProgressInputForm.tsx:206-211` 인라인 계산 → `calc입력기준금액(선택수주)`.
- `이력수정Sheet.tsx:61-66` → `calc입력기준금액(row.수주)`.

- 경고(`저장후경고`)·Δ%·현재 달성률은 같은 기준에서 파생되므로 따로 고칠 곳 없음.

### Task 4 — 기준을 화면에 드러내기

- 입력 폼 요약(505~515): "하도적용금액" 줄을 "% 기준 금액 (준공액 기준)" / "(수주금액 기준)"으로. 준공액 기준일 때는 수주금액 줄 아래 **준공액** 줄도 보인다.
- 수정 시트: % 입력 아래 한 줄 "준공액 기준" / "수주금액 기준".
- 문구는 사장님이 아니라 입력하는 사람(조성현·공무) 대상. 사장님 고지 불필요(매출 숫자 안 바뀜).
